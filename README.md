# Ashfall: Black Meridian

A round-based first-person survival shooter set in a decommissioned coastal
atmospheric research station after a failed storm-energy experiment. Hold twelve
rounds while the station physically changes around you.

Built in **Unity 6000.5.7f1** with URP. Every asset — geometry, textures,
materials, HUD sprites, enemy and weapon models — is generated from source in
this repository. Nothing is downloaded at build time.

> **Original work.** Ashfall: Black Meridian is inspired by the pacing
> conventions of round-based survival shooters as a genre. It is not affiliated
> with, endorsed by, or derived from any other title. All names, rules, code,
> art, audio design, UI, and level layout are original to this project.

## Quick start

```bash
git clone https://github.com/millZach/unique-zombies-game.git
cd unique-zombies-game
```

Open the folder with Unity Hub using editor version **6000.5.7f1**, then open
`Assets/Ashfall/Scenes/Main.unity` and press **Play**.

The scene is committed, so this works from a clean clone. If you press Play in
any other scene, a bootstrapper notices there is no `GameDirector` and loads
`Main` for you.

### Rebuilding everything from code

The entire scene — render pipeline asset, textures, materials, meshes, prefabs,
level geometry, lighting, nav graph, HUD — is generated by one command:

**`Ashfall ▸ Build Playable Scene`** (or `Ctrl`/`Cmd` + `Shift` + `B`)

Headless equivalent:

```bash
/home/zach/Unity/Hub/Editor/6000.5.7f1/Editor/Unity \
  -batchmode -nographics -projectPath "$PWD" \
  -executeMethod Ashfall.EditorTools.AshfallProjectBuilder.BuildFromCommandLine \
  -logFile /tmp/ashfall-build.log
```

This is deliberate: there is no hand-wired scene to break, and a regenerated
scene is byte-for-byte reproducible.

**First-time setup note.** TextMeshPro's essential resources must be imported
once before the HUD can build. They ship inside the uGUI package, so no download
is needed:

```bash
/home/zach/Unity/Hub/Editor/6000.5.7f1/Editor/Unity \
  -batchmode -nographics -projectPath "$PWD" \
  -executeMethod Ashfall.EditorTools.AshfallProjectBuilder.ImportTextMeshProEssentials \
  -logFile /tmp/ashfall-tmp.log
```

(In the editor GUI, `Window ▸ TextMeshPro ▸ Import TMP Essential Resources` does
the same thing. Omit `-quit`: the import is asynchronous and the script exits on
its own when it finishes.)

## The run

Twelve rounds. Kills and repairs pay **salvage**; salvage buys routes and
weapons. The run ends on death and restarts without leaving play mode.

### Map phases

The station changes state at rounds **3, 6, 9 and 12**. Each phase moves five
things at once — routes, lights, props, weather and storm exposure — because a
map that only swaps a light colour does not read as evolving.

| Round | Phase | What visibly changes |
| --- | --- | --- |
| 1–2 | **Standby** | Courtyard only. Amber emergency lamps, light rain, lab shutter boarded over. |
| 3–5 | **Breach** | Lab shutter fails open, boards blow away, torn shutter debris appears, storm lamps ignite, rain doubles. |
| 6–8 | **Surge** | Generator blast door powers open, generator coil rings light, courtyard conduits go live, rooftop storm exposure begins. First **Storm Brute**. |
| 9–11 | **Blackout** | Mains die — amber fades out, teal storm light takes over. Collapsed panels and a snapped beam drop into the courtyard. Catwalk spawns open. |
| 12 | **Black Meridian** | Roof hoarding tears away, roof hatch fails open, storm column overhead, maximum rain and lightning, rooftop spawns. Three brutes. |

### Routes

Three purchasable routes gate the map. Each also **fails open on its own** a few
rounds later, so a player who cannot afford one is not locked out forever.

| Route | Cost | Opens | Fails open at |
| --- | --- | --- | --- |
| Lab wing shutter | 950 | Courtyard → lab wing | Round 3 |
| Generator blast door | 1350 | Courtyard → generator room | Round 6 |
| Roof access hatch | 1600 | Generator catwalk → roof lane | Round 12 |

The map is a loop, not a corridor: the roof lane's west end is an unrailed drop
back into the lab wing. Enemies will not use it — the nav graph rejects a 5 m
fall — so it is a player-only escape.

### Weapons

| Weapon | Cost | Behaviour |
| --- | --- | --- |
| **Meridian sidearm** | starting | Semi-auto, 340 RPM, 14-round magazine, 38 damage, ×2.6 head shot. Accurate, cheap to feed. |
| **Breakwater** | 1250 | 9-pellet shotgun, 78 RPM, 6 shells, shell-at-a-time reload you can interrupt by firing. Dominant inside 6 m, useless past 19 m. |
| **Arc-9** | 1900 | Full-auto rail carbine, 690 RPM, 32-round magazine, 26 damage, tightest sights. The long-range answer. |

Owned weapons can be refilled at the same rack for a lower price, so the racks
stay useful all run.

### Enemies

| Enemy | From | Behaviour |
| --- | --- | --- |
| **Shambler** | Round 1 | 155 HP, 2.05 m/s. Hunched and wide. Staggers easily. |
| **Sprinter** | Round 3 | 95 HP, 4.85 m/s, lunges. Low, pitched forward, glowing ribs. |
| **Storm Brute** | Round 6 | 1250 HP, knocks the player back, 65% stagger resistance, always drops a power-up. |

Enemies tear boards off breaches to get in. Boarding them back up pays 20
salvage per plank and physically blocks the opening again.

### Power-ups

| Power-up | Effect |
| --- | --- |
| **Overcharge** | Weapon damage ×2.25 for 20 s |
| **Salvage Surge** | All salvage income ×2 for 25 s |
| **Last Stand** | The next lethal hit is survived instead of ending the run, plus 1.25 s of immunity, for 28 s |

Guaranteed drops on rounds 4, 6, 8, 10 and 12; random chance otherwise.

## Verification

Every command below was run against this repository. All are non-interactive.

```bash
UNITY=/home/zach/Unity/Hub/Editor/6000.5.7f1/Editor/Unity
```

**Compile:**
```bash
$UNITY -batchmode -nographics -quit -projectPath "$PWD" -logFile /tmp/ashfall-compile.log
grep -c "error CS" /tmp/ashfall-compile.log     # expect 0
```

**Regenerate the scene:**
```bash
$UNITY -batchmode -nographics -projectPath "$PWD" \
  -executeMethod Ashfall.EditorTools.AshfallProjectBuilder.BuildFromCommandLine \
  -logFile /tmp/ashfall-build.log
```

**Validate — checks critical references, gating, missing scripts, hitboxes:**
```bash
$UNITY -batchmode -nographics -projectPath "$PWD" \
  -executeMethod Ashfall.EditorTools.AshfallValidation.ValidateFromCommandLine \
  -logFile /tmp/ashfall-validate.log     # exit 0 = pass
```

Also available as **`Ashfall ▸ Validate Project`** in the editor. It verifies
that each zone is reachable with routes open and *unreachable* with them closed,
that every spawn point can reach the player, that no component has a missing
script, and that every enemy prefab has a critical hitbox on the right layer.

**Navigation diagnosis — `Ashfall ▸ Diagnose Navigation`:**
```bash
$UNITY -batchmode -nographics -projectPath "$PWD" \
  -executeMethod Ashfall.EditorTools.AshfallNavDiagnostics.DiagnoseFromCommandLine \
  -logFile /tmp/ashfall-nav.log
```
Reports disconnected islands in the baked graph and where their boundaries are.

**Tests:**
```bash
$UNITY -batchmode -nographics -projectPath "$PWD" \
  -runTests -testPlatform EditMode -testResults /tmp/edit-results.xml \
  -logFile /tmp/ashfall-edit-tests.log

$UNITY -batchmode -nographics -projectPath "$PWD" \
  -runTests -testPlatform PlayMode -testResults /tmp/play-results.xml \
  -logFile /tmp/ashfall-play-tests.log
```

86 edit-mode tests cover round composition, the phase schedule, weapon
ammo/cadence/damage maths, A* pathfinding with gates, generated weapon/enemy
geometry, and the pooled audio director. The 24-test play-mode suite loads the
real scene and asserts the loop actually turns over: enemies spawn and close
distance, kills pay salvage, routes cost money and open gates, power-ups apply
and expire, phases change the world, restart resets everything, and each major
gameplay/audio event reaches the audio director.

**Blender source assets:**
```bash
/snap/bin/blender --background --python Tools/Blender/generate_assets.py
```
24 assets, ~4,000 triangles, exported to FBX + GLB + .blend under
`Tools/Blender/Output/` (git-ignored). See `Tools/Blender/README.md`.

**Player build:**
```bash
$UNITY -batchmode -nographics -projectPath "$PWD" \
  -executeMethod Ashfall.EditorTools.AshfallPlayerBuild.BuildLinuxFromCommandLine \
  -logFile /tmp/ashfall-player.log
```
Outputs to `Builds/Linux/Ashfall.x86_64` (git-ignored).

**Audio source and inspection:**
```bash
/usr/bin/python3 Tools/Audio/generate_audio.py
/usr/bin/python3 Tools/Audio/inspect_audio.py --png /tmp/ashfall-audio.png
```
The generator creates 29 deterministic, original PCM WAV clips under
`Assets/Ashfall/Audio/`; the inspector checks for silence, clipping, DC offset,
and non-finite samples. Audio is wired through the pooled `AudioDirector` in the
scene. The Meshcaster art-pass prompts, 500-credit ledger, approval gate, and
six-slot import workflow are documented in `Docs/MeshcasterArtPass.md`.

### Architecture notes

- **No NavMesh.** The AI Navigation package does not resolve offline for this
  editor install, so navigation is a baked waypoint graph with A* and **gated
  links**. That buys something NavMesh would have made awkward: closing a door
  re-routes every enemy on their next path request, so the map evolving is
  something the AI actually feels.
- **Input is built in code**, not loaded from an `.inputactions` asset. That
  removes a class of failure (missing GUID, stale generated wrapper) and means
  the scene builder has nothing to wire. A legacy fallback keeps the project
  compiling if the Input System package is ever absent.
- **Hitscan, not projectiles.** At these ranges the difference is invisible, and
  raycasts stay exact under any frame rate.
- **Stairs use a single sloped collider** under stepped visual geometry.
  Per-step colliders bake as walls in the nav graph.

## Known limitations

Honest list of what is not done.

- **Audio is now included.** Twenty-nine deterministic, license-safe WAV clips
  cover weapons, reloads, impacts, enemies, player damage, power-ups, purchases,
  round stingers, and storm ambience. They route through a pooled audio director
  with 2D/3D spatialization and anti-spam guards. The Linux environment has no
  physical audio device, so verification uses signal inspection plus editor and
  PlayMode counters rather than claiming a listening test.
- **Meshcaster output is staged, not fabricated.** This pass includes six empty
  import slots, curved procedural fallback bodies, a non-networking importer, and
  exact Meshcaster prompts/settings in `Docs/MeshcasterArtPass.md`. No paid
  generation was run by the agent; use the documented human Preview/Approve flow
  under the hard 500-credit cap, then copy approved prefabs/FBX files into the
  slots. The procedural fallback remains playable until then.
- **Not visually inspected in a running window.** Development was entirely
  headless — no display was available. Geometry, lighting, materials and HUD
  layout are verified by construction (dimension checks, nav bakes, reference
  validation, play-mode assertions) rather than by looking at rendered frames.
  Expect to want to nudge HUD spacing and light intensities once you see it.
- **Solo only.** No multiplayer, no split screen.
- **One map.** The station is the whole slice.
- **Enemies are not animated.** All motion is procedural — gait bob, lean,
  attack windup, death collapse. There are no skinned meshes or animation clips.
- **The Blender exports are optional.** The game does not import them; it builds
  its own primitives in C#. They are provided as an upgrade path, and swapping
  them in is manual.
- **No save system.** Progress is per-run only.
- **Power-ups do not stack**, they refresh their own timer.
- **Round 12 is the end of the slice.** Clearing it shows a completion banner;
  there is no endless mode.
- **11 isolated nav nodes** exist on top of canopy and hoarding geometry. They
  are unreachable islands that cost nothing and are never pathed to; the
  diagnostic tool reports them rather than hiding them.
